# 配置文件审计（dsh-env-audit）

**什么时候用**：想确认环境配置文件本身有没有把凭据暴露出去 —— 会不会被提交、权限对不对、里面是不是明文、有没有模板。
用户会说：「.env 会不会被提交」「我的密钥是不是进 git 了」「环境变量配置有问题吗」「上线前查一下配置」「.env 权限对吗」。

## 怎么用

```bash
dsh-env-audit --root <项目目录>
```

## 怎么读结果

按这个顺序处理命中：

1. **`ENV-NOT-IGNORED`（先修这条）** —— `.env` 没被忽略。在 `.gitignore` 加一行 `.env`。**如果它曾经被提交过**，光加忽略没用：先 `git rm --cached .env`，再用 `git log --all -- .env` 确认历史，然后把这个密钥当成已泄露**轮换**掉。
2. **`ENV-PLAINTEXT`** —— 文件里是明文。真实值抽到密钥管理/运行时注入，文件里只留 `${VAR}` 或占位值。报告里只显示键名，值不会被打出来。
3. **`ENV-FILE-PERM`** —— `chmod 600 .env`。顺带看看上级目录，以及自动生成 `.env` 的脚本/容器是不是又用 644 建了一遍。（仅 POSIX 有意义。）
4. **`ENV-NO-EXAMPLE`** —— 补一份只含键名和占位值的 `.env.example`，README 里指向它。这能防住「新人找同事要一份真实 `.env` 直接复制」这条最常见的扩散路径。
5. **`ENV-HARDCODED-CONFIG`** —— 内网地址写死在代码里。是提示确认项，不是结论。

## 不要做什么

- 不要把「命中」直接当成违规 —— 它是提示你确认，不是判定
- 不要用它替代密钥轮换 —— 工具只发现暴露面，不解除暴露
- 不要拿它扫代码里的密钥字面量 —— 那是 `dsh-secret-scan`；这个只审配置文件本身
- 不要指望它告诉你「历史里有没有提交过 `.env`」—— 它不读 git 索引，只做离线文件审计
